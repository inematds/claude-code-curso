🐍 Python + Claude Code

Setup de Python con pyenv, virtual environments, dependencias y tus primeros scripts asistidos por IA.

Qué es:

Instalar y administrar versiones de Python con pyenv o python3 nativo.

Por qué aprender:

Sin la versión correcta, nada funciona. Claude Code necesita un Python consistente.

Conceptos clave:

pyenv install, pyenv local, python3 --version, PATH.

Qué es:

Los entornos virtuales aíslan las dependencias por proyecto.

Por qué aprender:

Evita conflictos y garantiza la reproducibilidad.

Conceptos clave:

python3 -m venv, uv venv, activate, .venv en .gitignore.

Qué es:

Instalar paquetes con pip o uv (una alternativa rápida a pip).

Por qué aprender:

Claude Code genera requirements.txt; debes saber instalarlo y fijar las versiones.

Conceptos clave:

pip install, pip freeze, requirements.txt, uv pip install.

Qué es:

Escribir scripts sencillos de Python con ayuda de Claude Code.

Por qué aprender:

Automatizar tareas repetitivas es el primer paso para hacer "ship".

Conceptos clave:

argparse, pathlib, sys.argv, if __name__.

Qué es:

Usar Claude Code para identificar y corregir bugs rápidamente.

Por qué aprender:

El debug ocupa el 50% del tiempo de desarrollo; la IA lo reduce drásticamente.

Conceptos clave:

Pegar el traceback, pedir una corrección, breakpoints, pdb.

Qué es:

Agregar type hints con ayuda de Claude para lograr un código más robusto.

Por qué aprender:

Los type hints mejoran el autocompletado y reducen los errores en runtime.

Conceptos clave:

str, int, list[str], Optional, TypedDict, mypy.

⚡ Automatización de scripts

Web scraping, procesamiento de archivos, transformaciones de datos y programación con cron.

Qué es:

Extraer datos de páginas web con requests y BeautifulSoup.

Por qué aprender:

La automatización comienza con datos; el scraping es la puerta de entrada.

Conceptos clave:

requests.get, BeautifulSoup, selectors, rate limiting.

Qué es:

Procesar cientos de archivos con pathlib y glob.

Por qué aprender:

Las tareas manuales que llevan horas se convierten en un script de 20 líneas.

Conceptos clave:

pathlib.Path, glob, shutil, renombrar en masa.

Qué es:

Leer, transformar y exportar datos entre CSV, JSON y otros formatos.

Por qué aprender:

Todo pipeline de datos necesita convertir formatos.

Conceptos clave:

csv.DictReader, json.load/dump, pandas básico.

Qué es:

Programar scripts para que se ejecuten automáticamente con cron/systemd.

Por qué aprender:

La automatización real = ejecutarse sin intervención humana.

Conceptos clave:

crontab -e, sintaxis de cron, logging, temporizadores de systemd.

Qué es:

Consumir APIs REST de servicios como GitHub, Slack, etc.

Por qué aprender:

Los scripts potentes conectan servicios entre sí.

Conceptos clave:

requests, headers, auth tokens, paginación.

Qué es:

try/except, logging, retries y graceful degradation.

Por qué aprender:

Un script de producción no puede fallar en silencio.

Conceptos clave:

try/except, logging module, tenacity, exit codes.

🚀 FastAPI y servicios web

Crear APIs profesionales con FastAPI, Pydantic y documentación automática.

Qué es:

Crear tu primera API con FastAPI en minutos.

Por qué aprender:

FastAPI es el framework de Python más rápido para APIs modernas.

Conceptos clave:

FastAPI(), @app.get, uvicorn, async.

Qué es:

Definir esquemas de datos con Pydantic BaseModel.

Por qué aprender:

La validación automática elimina errores de datos en la entrada.

Conceptos clave:

BaseModel, Field, validators, response_model.

Qué es:

Implementar las cuatro operaciones básicas de cualquier API.

Por qué aprender:

CRUD es el estándar universal; toda API empieza aquí.

Conceptos clave:

@app.post/get/put/delete, códigos de estado, parámetros de ruta.

Qué es:

Agregar CORS, rate limiting y autenticación básica.

Por qué aprender:

Una API sin auth es una invitación al desastre.

Conceptos clave:

CORSMiddleware, Depends, OAuth2, API keys.

Qué es:

FastAPI genera Swagger UI y ReDoc automáticamente.

Por qué aprender:

Documentación viva que facilita la depuración y la incorporación de nuevos miembros.

Conceptos clave:

/docs, /redoc, OpenAPI schema, tags.

Qué es:

Ejecutar localmente con uvicorn y hacer deploy remoto con gunicorn.

Por qué aprender:

Una API que solo funciona localmente no es un producto.

Conceptos clave:

uvicorn, gunicorn, reverse proxy, HTTPS.

🧪 Testing automatizado

pytest, fixtures, mocks, coverage y TDD con Claude Code.

Qué es:

Escribir y ejecutar pruebas con pytest.

Por qué aprender:

Las pruebas son la red de seguridad que permite iterar rápidamente.

Conceptos clave:

test_ prefix, assert, pytest -v, markers.

Qué es:

Las fixtures preparan el estado; conftest.py lo comparte entre archivos.

Por qué aprender:

Evita duplicaciones y mantiene las pruebas limpias.

Conceptos clave:

@pytest.fixture, scope, conftest.py, parametrize.

Qué es:

Simular dependencias externas con unittest.mock.

Por qué aprender:

Probar sin depender de una base de datos, API o sistema de archivos.

Conceptos clave:

Mock, patch, MagicMock, side_effect.

Qué es:

Medir qué líneas de código ejercitan las pruebas.

Por qué aprender:

No sabes qué no está probado hasta que lo mides.

Conceptos clave:

pytest-cov, --cov=src, coverage html, branch coverage.

Qué es:

Escribir la prueba antes del código, con Claude generando la implementación.

Por qué aprender:

TDD + IA es un superpoder: tú defines qué, la IA hace cómo.

Conceptos clave:

Red-green-refactor, pruebas primero, especificación mediante ejemplos.

Qué es:

Ejecutar pruebas automáticamente en cada push/PR.

Por qué aprender:

CI garantiza que nadie (ni siquiera la IA) rompa lo que funciona.

Conceptos clave:

GitHub Actions, paso de pytest, insignia de cobertura, fail fast.

🐳 Deploy e infraestructura

Docker, deploy en la nube, gestión de entornos y monitoreo.

Qué es:

Empaquetar tu app Python en un contenedor Docker.

Por qué aprender:

"Funciona en mi máquina" se convierte en "funciona en cualquier lugar".

Conceptos clave:

Dockerfile, docker build, docker run, multi-stage.

Qué es:

Orquestar varios contenedores (app + DB + redis) con un YAML.

Por qué aprender:

Las apps reales tienen más de un servicio.

Conceptos clave:

docker-compose.yml, services, volumes, networks.

Qué es:

Deploy con un comando en plataformas como Railway o Fly.io.

Por qué aprender:

Cloud PaaS es la forma más rápida de ponerlo en marcha.

Conceptos clave:

railway deploy, fly launch, Procfile, buildpacks.

Qué es:

Gestionar .env, secrets y configuraciones por entorno (dev/staging/prod).

Por qué aprender:

Secrets expuestos = desastre; configuración incorrecta = tiempo de inactividad.

Conceptos clave:

.env, python-dotenv, pydantic-settings, 12-factor.

Qué es:

Structured logging, health checks y alertas básicas.

Por qué aprender:

Sin monitoring, solo descubres los problemas cuando el usuario se queja.

Conceptos clave:

structlog, /health endpoint, uptime monitoring.

Qué es:

Escalado horizontal vs. vertical, caché y cuándo tenerlo en cuenta.

Por qué aprender:

Saber cuándo (y cuándo NO) escalar evita el sobrediseño.

Conceptos clave:

Réplicas, balanceador de carga, caché de Redis, optimización prematura.

🚢 Ship Your Product

Mentalidad MVP, lista de verificación de lanzamiento y ciclo de iteración posterior al lanzamiento.

Qué es:

Construir el mínimo viable que aporte valor real.

Por qué aprender:

El perfeccionismo mata proyectos; un MVP los lanza.

Conceptos clave:

MVP, recorte del alcance, «suficientemente bueno», tiempo limitado.

Qué es:

Decidir qué NO hacer es tan importante como decidir qué hacer.

Por qué aprender:

Con IA, puedes construir rápido; el cuello de botella pasa a ser decidir QUÉ.

Conceptos clave:

Debe/debería/podría/no se hará, impacto frente a esfuerzo, priorización del backlog.

Qué es:

Lista de verificación previa al lanzamiento: pruebas, documentación, monitoreo, rollback.

Por qué aprender:

Los lanzamientos sin checklist son lanzamientos con sorpresas.

Conceptos clave:

Antes del lanzamiento, pruebas smoke, plan de rollback, feature flags.

Qué es:

Recopilar feedback real y convertirlo en mejoras.

Por qué aprender:

Un producto sin feedback es pura adivinación.

Conceptos clave:

Comentarios de usuarios, analíticas, informes de errores, solicitudes de funciones.

Qué es:

Ciclos cortos de construir-medir-aprender después del lanzamiento.

Por qué aprender:

El lanzamiento no es el final; es el comienzo.

Conceptos clave:

Sprints, changelogs, semver, continuous deployment.

Qué es:

Opciones después de dominar Python + Claude Code: SaaS, open source, consultoría.

Por qué aprender:

Saber cuál es el destino ayuda a elegir el siguiente paso.

Conceptos clave:

SaaS, código abierto, trabajo freelance, portafolio, comunidad.
