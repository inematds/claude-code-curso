1

🎯 Mentalidad MVP

MVP no es un producto malo. Es la versión más pequeña que resuelve el problema real de alguien. La trampa clásica: seguir puliendo funciones que nadie pidió mientras el problema central sigue sin resolverse. Claude Code acelera la construcción, pero necesitas saber qué construir.

Pregúntate: "Si tuviera solo 1 pantalla y 1 acción, ¿cuál sería?" Esa respuesta es el núcleo de tu MVP. Todo lo demás va al backlog. Dile a Claude Code: "cria o fluxo minimo pra [problema X]" y resiste la tentación de agregar «solo un campo más».

En 1 frase: MVP = resolver UN problema real, no diez a medias.

2

🔪 Priorización ruthless

Toda feature que agregas tiene un costo: código que mantener, bugs que corregir, complejidad que explicar. La priorización implacable dice NO al 90% de las ideas para que el 10% restante sea excelente. Usa la matriz de impacto frente a esfuerzo: alto impacto + bajo esfuerzo = hazlo ahora. El resto puede esperar.

priorizacao.md
## Matriz de Priorizacao

| Feature         | Impacto | Esforco | Decisao      |
|-----------------|---------|---------|--------------|
| Auth basico     | Alto    | Baixo   | MVP - faz    |
| Dashboard admin | Medio   | Alto    | v2 - espera  |
| Dark mode       | Baixo   | Baixo   | Nice-to-have |
| Notificacoes    | Alto    | Medio   | v1.1 - logo  |
| Multi-idioma    | Baixo   | Alto    | Backlog      |

Trampa clásica

"¡Pero es solo una feature más!" No. Cada feature "pequeña" se acumula. 20 features "pequeñas" = un producto confuso. Prioriza sin piedad.

En 1 frase: priorizar = decidir qué NO hacer para que lo esencial quede excelente.

3

✅ Lista de verificación para el lanzamiento

Antes de lanzar, revisa esta lista. No se trata de la perfección. Se trata de no fallar frente al usuario. Claude Code ayuda: "audita esse projeto contra a launch checklist".

launch-checklist.md
## Pre-Launch Checklist

- [ ] README claro (o que faz, como instalar, como usar)
- [ ] .env.example com todas as variaveis documentadas
- [ ] Testes passando (pytest + CI verde)
- [ ] /health endpoint respondendo
- [ ] HTTPS configurado
- [ ] Secrets fora do repositorio (.gitignore)
- [ ] Backup do banco de dados
- [ ] Monitoring + alertas basicos
- [ ] Pagina de erro customizada (404, 500)
- [ ] Um usuario real testou antes de voce

Cada elemento tiene un motivo. Un README confuso = nadie lo adopta. Secrets expuestos = desastre. Un usuario real haciendo pruebas = errores que nunca verías. La lista de verificación no es burocracia: es la red de seguridad mínima.

En 1 frase: launch checklist = red de seguridad contra los errores más comunes del primer deploy.

4

🔄 Ciclo de retroalimentación

¿Ya lo lanzaste? Ahora escucha. El bucle de retroalimentación es el motor de evolución del producto. Métricas cuantitativas (quién lo usó, dónde abandonó) y cualitativas (qué dijeron, qué pidieron). Sin un ciclo de retroalimentación, estás programando a ciegas.

Herramientas mínimas: analíticas básicas (Plausible, Umami), un canal directo con los usuarios (formulario, correo electrónico, Discord/Telegram) y un lugar para registrar lo que escuchaste (Notion, GitHub Issues, incluso un .md en el repo). El secreto: responder rápido. Un bug reportado y corregido el mismo día vale más que 10 features nuevas.

En 1 frase: lanza, escucha, ajusta, repite. Sin un ciclo de retroalimentación, estás adivinando.

5

🔁 Iteración después del lanzamiento

El producto no está "listo" en el lanzamiento. Está empezando. La iteración posterior al lanzamiento sigue este ritmo: corregir errores críticos (día 1-3), ajustar la UX según los comentarios (semana 1-2), agregar la función más solicitada (semana 3-4). Los lanzamientos pequeños y frecuentes > las grandes actualizaciones esporádicas.

Con Claude Code, el ciclo de iteración se acorta drásticamente. Bug reportado -> "corrige esse bug: [descricao]" -> pruebas -> deploy. Lo que llevaba días ahora lleva horas. Aprovecha esto: la velocidad de respuesta es una ventaja competitiva real para proyectos pequeños.

ritmo de iteración
## Ciclo Pos-Launch

Dia 1-3:   Hotfixes (bugs criticos, crashes)
Semana 1:  Quick wins do feedback (UX, copy, fluxo)
Semana 2:  Refactor se necessario (divida tecnica)
Semana 3:  Feature #1 mais pedida
Semana 4:  Retrospectiva + planejar proximo ciclo

Regra: nunca fique mais de 2 semanas sem release.

En 1 frase: las releases pequeñas y frecuentes superan a las megaactualizaciones esporádicas.

6

🌅 Qué sigue

Completaste las 5 rutas. Sabes instalar y configurar Claude Code (T1), usar los modos Plan y Loop (T2), conectar MCP (T3), orquestar subagentes y Git (T4), y construir y desplegar con Python (T5). Esto no es el final. Es el comienzo de una nueva forma de trabajar.

El siguiente paso es tuyo. Puede ser un SaaS, una herramienta interna, una automatización que ahorre horas por semana o un proyecto open source que ayude a otras personas. Claude Code es el copiloto. Tú eres quien pilota. Ship it.

Opciones posibles

  • SaaS: transforma tu MVP en un producto de pago con Stripe + auth + multi-tenant.
  • Open Source: publica en GitHub, documenta bien, atrae colaboradores.
  • Automatización personal: bots, scrapers, pipelines que se ejecutan 24/7 en tu servidor.
  • Trabajo freelance/consultoría: usa Claude Code para entregar proyectos 5 veces más rápido.
  • Enseña: quien aprende enseñando consolida. Comparte lo que construiste.

En 1 frase: El curso termina aquí; lo que construyas a partir de ahora depende de ti.
