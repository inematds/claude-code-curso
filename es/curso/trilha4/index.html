Subagentes — Conceptos

Qué son los subagentes, la herramienta Task y cuándo usar el paralelismo.

Qué es:

Los subagentes son instancias de Claude Code que el agente principal lanza para ejecutar tareas aisladas.

Por qué aprender:

Permite escalar el trabajo sin contaminar el contexto del agente principal.

Conceptos clave:

Padre-hijo; aislamiento de contexto; delegación.

Qué es:

La herramienta interna de Claude Code que crea subagentes con su propio prompt y contexto.

Por qué aprender:

Es la interfaz principal para orquestar el trabajo en paralelo.

Conceptos clave:

Task(prompt); retorno del resultado; alcance limitado.

Qué es:

Los subagentes pueden tener distintos niveles de permisos: lectura, escritura o background.

Por qué aprender:

Elegir el tipo correcto evita conflictos y reduce riesgos.

Conceptos clave:

Principio del menor privilegio; agentes especializados.

Qué es:

El padre envía instrucciones y contexto; el hijo devuelve un resultado textual al terminar.

Por qué aprender:

Entender el flujo evita la pérdida de información entre agentes.

Conceptos clave:

Prompt de entrada; respuesta estructurada; sin estado compartido.

Qué es:

Los worktrees de git permiten que cada subagente trabaje en archivos sin entrar en conflicto con los demás.

Por qué aprender:

Sin aislamiento, los agentes paralelos se estorban entre sí.

Conceptos clave:

git worktree; rama temporal; merge posterior.

Qué es:

Los subagentes tienen un costo adicional de contexto y uso. No todas las tareas justifican el paralelismo.

Por qué aprender:

Evita gastar tokens innecesariamente en tareas simples.

Conceptos clave:

Costos operativos frente a beneficios; tareas independientes; complejidad mínima.

Paralelismo real

Lanza varios agentes, recopila resultados y gestiona errores en paralelo.

Qué es:

Disparar varias herramientas Task simultáneamente para tareas independientes.

Qué es:

Identificar las tareas que no dependen unas de otras para ejecutarlas simultáneamente.

Qué es:

Usar git worktree add para crear espacios de trabajo aislados por agente.

Qué es:

Ejecutar tareas largas en segundo plano mientras el agente principal continúa.

Qué es:

Reunir los resultados de todos los subagentes y consolidarlos en un resultado final.

Qué es:

Estrategias para gestionar fallas parciales: retry, skip o abort.

Patrones multiagente

Patrones arquitectónicos: fan-out/in, pipelines, especialistas y control de costos.

Qué es:

Distribuir el trabajo entre N agentes y reunir los resultados en un único lugar.

Qué es:

Encadenar agentes donde el resultado de uno alimenta al siguiente.

Qué es:

Un agente explora el codebase, otro planifica y otro ejecuta. Separación de responsabilidades.

Qué es:

Agentes con prompts específicos para pruebas, docs, lint o seguridad.

Qué es:

Patrones de retry, fallback y circuit-breaker adaptados para agentes de IA.

Qué es:

Limita los tokens por subagente, usa modelos más pequeños para tareas simples y mide el ROI.

Git con IA — Control de versiones

Commits semánticos, staging inteligente y conflictos de merge con Claude.

Qué es:

Claude analiza el diff y genera mensajes de commit según el estándar conventional commits.

Qué es:

Claude selecciona archivos relacionados lógicamente para commits atómicos.

Qué es:

Pídele a Claude que revise el diff antes de confirmar, para detectar bugs e inconsistencias.

Qué es:

Claude entiende el contexto de ambos lados y resuelve conflictos semánticamente.

Qué es:

Usar branches cortas y enfocadas que facilitan el trabajo del agente.

Qué es:

Proteger secretos (.env, keys) y evitar que el agente haga commit de archivos sensibles.
