1

Commits semánticos con Claude

Cuando le pides a Claude que haga un commit, analiza el diff, identifica el tipo de cambio (feat, fix, refactor, docs, etc.) y genera un mensaje con el formato conventional commits. Esto mantiene el historial legible y facilita los changelogs automáticos.

commit-semantico.sh
# Peca ao Claude para commitar as mudancas atuais
# Ele vai:
# 1. Rodar git status e git diff
# 2. Analisar o que mudou
# 3. Gerar mensagem semantica
# 4. Commitar com a mensagem

# Prompt: "commita essas mudancas com mensagem semantica"
# Output: git commit -m "feat(auth): add JWT refresh token rotation"

En 1 frase: Claude analiza el diff y genera commits semánticos (feat/fix/refactor) automáticamente.

2

Staging inteligente

Claude prefiere agregar archivos específicos al staging (git add arquivo.ts) en lugar de git add -A. Agrupa archivos relacionados lógicamente en un mismo commit, creando commits atómicos en los que cada uno representa un único cambio coherente. Esto es fundamental: si necesitas revertir, reviertes una unidad lógica, no un conjunto de cambios mezclados.

En 1 frase: Claude agrupa archivos relacionados en commits atómicos; nunca usa git add -A a ciegas.

3

Revisión automatizada del diff

Antes de hacer commit, pídele a Claude: "revisa el diff actual". Ejecuta git diff --staged, analiza los cambios y reporta: posibles bugs, inconsistencias de estilo, lógica rota, imports faltantes. Es como tener un revisor de código instantáneo antes de cada commit.

diff-review.sh
# Pedir review do diff antes de commitar
git diff --staged | head -200
# Prompt: "analisa esse diff e me diz se tem algum problema"

En 1 frase: Claude revisa el diff antes del commit y detecta errores antes de que entren en el historial.

4

Conflictos de merge

Los conflictos de merge son la pesadilla del control de versiones. Con Claude, puedes pedir: "resuelve los merge conflicts del archivo X". Entiende el contexto semántico de ambos lados, no hace una resolución mecánica (aceptar uno u otro), sino que integra las intenciones de ambas ramas. En conflictos complejos, puede preguntarte qué comportamiento prefieres.

En 1 frase: Claude resuelve los conflictos de merge semánticamente, integrando la intención de ambas branches.

5

Estrategia de branching

Con IA en el workflow, las branches cortas funcionan mejor. El patrón: crea una branch por feature/fix, deja que Claude trabaje en ella y haz merge rápido. Las branches de larga duración acumulan divergencias y dificultan el trabajo del agente. Prefiere feat/add-auth que dura 1-2 días a develop que acumula semanas.

En 1 frase: las branches cortas y enfocadas son las mejores aliadas del agente de IA.

6

.gitignore y seguridad

Claude Code tiene reglas de seguridad integradas: nunca hagas commit de archivos .env, credentials o claves sin aviso explícito. Pero también debes mantener actualizado tu .gitignore. Pídele a Claude que audite: "verifica si hay algún secreto que no esté en .gitignore". Prevenir es mejor que remediar una filtración de credenciales.

Nunca hagas commit

.env, *.pem, credentials.json, *.key, node_modules/, .claude/ (que contiene worktrees temporales). Si se filtró, rota las claves de inmediato.

En 1 frase: .gitignore actualizado + Claude atento = cero filtraciones de secretos.
