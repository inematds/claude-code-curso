⚡ Atajos de teclado esenciales

🧠 Imagínalo así: los atajos de teclado en Claude Code son como los atajos en Vim. Al principio los ignoras; después de aprenderlos, no puedes vivir sin ellos. La diferencia es que aquí solo son 5-6 teclas que cubren todo.

Dentro de la sesión interactiva de Claude Code, algunas teclas tienen un comportamiento especial que acelera drásticamente tu workflow. El secreto es que son pocas: cinco atajos cubren el 95% de la interacción. Conocer estas cinco teclas transforma la experiencia de «escribir y esperar» a «controlar el flujo con precisión». Es la diferencia entre conducir un auto automático y uno manual: en el automático quedas a merced de la IA; en el manual decides cuándo frenar, cuándo acelerar y cuándo retroceder.

El más importante de todos es el Escape: cancela la operación actual y te devuelve al prompt limpio. Cuando Claude está editando un archivo y notas que va por el camino equivocado, Escape detiene todo. Después viene el Tab para aceptar sugerencias del autocompletado, Ctrl+C para interrumpir una generación larga que ya dio lo que tenía que dar, Shift+Tab para rechazar una sugerencia, y Enter doble para enviar mensajes de varias líneas. Con estos cinco, puedes navegar por cualquier sesión.

✓ Atajos esenciales

  • • Escape — cancela la acción actual / vuelve al prompt
  • • Tab — acepta sugerencia / autocompletado
  • • Ctrl+C — interrumpe la generación en curso
  • • Shift+Tab — rechaza la sugerencia
  • • Enter doble — envía un mensaje de varias líneas

→ Consejos de navegación

  • • Flecha hacia arriba — editar el último mensaje
  • • Ctrl+L — limpiar la pantalla (sin perder el contexto)
  • • / al inicio: abre slash commands
  • • @ — referenciar un archivo por nombre
  • • Pega una imagen — análisis visual automático

💡 Consejo: practica los atajos

En tu próxima sesión con Claude Code, oblígate a usar solo atajos durante 10 minutos. Pide algo, cancela con Escape, vuelve a pedirlo, acepta con Tab, interrumpe con Ctrl+C. En menos de una hora ya estarás en piloto automático y nunca volverás al modo lento.

En 1 frase: Escape, Tab, Ctrl+C, Shift+Tab y Enter doble cubren el 95% de la interacción.

🔧 Slash commands: el panel de control

🧠 Imagínalo así: los slash commands son el panel de control oculto de Claude Code. Escribes /, apareció un menú. Es como el command palette de VS Code, pero dentro de la conversación con la IA.

Dentro de una sesión interactiva, escribe / al inicio del mensaje activa los slash commands. Controlan la sesión sin gastar tokens de conversación. Mientras que un mensaje normal se envía al modelo (y consume contexto), un slash command se ejecuta localmente: no cuesta nada, actúa de inmediato.

Los más usados forman un kit básico que todo usuario debería memorizar. /help enumera todo lo que está disponible. /clear reinicia el contexto de la conversación (útil cuando el contexto quedó contaminado). /compact comprime la conversación en un resumen más corto para liberar espacio. /model muestra o cambia el modelo. /memory guarda preferencias que persisten entre sesiones. /cost muestra cuánto gastaste en la sesión. Y /resume retoma una sesión anterior.

slash commands esenciales 
/help       — lista todos os comandos disponíveis
/clear      — limpa o contexto da conversa atual
/compact    — comprime o contexto para liberar espaço
/model      — ver ou trocar o modelo em uso
/memory     — salvar uma nota persistente
/resume     — retomar sessão anterior
/cost       — ver quanto gastou na sessão atual
/config     — abrir configurações

/help

El punto de partida. Muestra todo lo que está disponible. Ejecútalo cuando te pierdas.

/clear

Borra todo el contexto. Es útil cuando quieres empezar de nuevo sin cerrar la terminal.

/compact

Comprime la conversación en un resumen para liberar contexto. Úsalo antes de que se llene el contexto.

/model

Muestra qué modelo está activo. Puedes cambiar entre Opus y Sonnet sin salir de la sesión.

/memory

Guarda una preferencia que persiste entre sesiones. Ejemplo: "usa siempre TypeScript".

En 1 frase: escribe / para acceder al panel de control de Claude Code dentro de la sesión.

3

🧠 Modelo y ventana de contexto

🧠 Imagínalo así: El modelo es el cerebro; la ventana de contexto es la memoria de trabajo. Imagina que Claude tiene una mesa de trabajo con espacio limitado. Todo lo que dices y todo lo que lee va a la mesa. Cuando se llena, algo se cae.

Claude Code usa modelos de la familia Claude de Anthropic. El predeterminado suele ser el Claude Sonnet (rápido y capaz para la mayoría de las tareas), pero puedes cambiar a Claude Opus (más profundo, mejor para el razonamiento complejo y los codebases grandes) en cualquier momento con /model o --model. Entender la diferencia entre ellos y saber cuándo cambiar es una habilidad que distingue a los usuarios eficientes de quienes desperdician dinero o tiempo.

A ventana de contexto es el límite de lo que el modelo ve al mismo tiempo: todo lo que dijiste, todo lo que leyó, todos los archivos inspeccionados y todas las respuestas generadas. La ventana de contexto de Claude es de aproximadamente 200k tokens (cerca de 150k palabras). Parece mucho, pero un codebase promedio consume eso rápido. Cada archivo leído, cada respuesta generada, cada CLAUDE.md cargado consume tokens de esta ventana. Cuando se acaba el espacio, Claude empieza a olvidar el inicio de la conversación.

✓ Claude Sonnet

  • • Rápido y responsivo
  • • Bueno para tareas comunes
  • • Más barato por token
  • • Ideal para ediciones rápidas y preguntas

→ Claude Opus

  • • Más profundo y preciso
  • • Mejor en razonamiento complejo
  • • Más caro por token
  • • Ideal para refactorización y arquitectura

⚠️ Señales de contexto lleno

Claude empieza a olvidar instrucciones del principio, repite preguntas que ya respondió, ignora las reglas de CLAUDE.md o simplemente deja de funcionar bien. Cuando lo notes, usa /compact o inicia una sesión nueva.

En 1 frase: Sonnet = rápido, Opus = profundo; 200k tokens es la mesa de trabajo y todo compite por espacio.

4

💾 Sesiones y /resume

🧠 Imagínalo así: cerrar la terminal no borra la conversación. Es como cerrar un libro con un separador. Cuando vuelves, /resume abre en la página correcta.

Claude Code guarda las sesiones automáticamente en el disco local. Cada conversación tiene un session ID y queda guardada en ~/.claude/. Esto significa que cerrar la terminal, apagar la computadora o incluso cambiar de pestaña no hace que pierdas nada. La sesión sigue ahí, esperando que vuelvas.

Para retomar, tienes dos opciones: claude --resume en la línea de comandos (antes de abrir una sesión nueva) o /resume desde dentro de una sesión ya abierta. Ambos muestran un selector con las sesiones recientes para que elijas. También es posible retomar una sesión específica por su ID: claude --resume SESSION_ID.

En la práctica, el ritmo ideal es trabajar en una sesión durante 1-2 horas, hacer commits de los checkpoints en git y, cuando se llene el contexto, iniciar una sesión nueva. Si necesitas retomar algo del día anterior, --resume recupera. Pero recuerda: las sesiones muy largas degradan la calidad de las respuestas porque el contexto se llena. A veces es mejor empezar de cero y dejar que CLAUDE.md cargue el contexto esencial.

retomando sesiones 
# retomar a última sessão
claude --resume

# dentro de uma sessão, retomar outra
/resume

# continuar conversa específica por ID
claude --resume SESSION_ID

# listar sessões recentes
claude --resume  (mostra picker interativo)

💡 Sesión nueva vs. resume

Si estás retomando el mismo trabajo de ayer, usa --resume. Si estás empezando una tarea diferente (incluso en el mismo proyecto), inicia una sesión nueva. Mezclar contextos de tareas distintas satura la ventana y degrada la calidad.

En 1 frase: las sesiones persisten en el disco; --resume o /resume retoma desde donde te quedaste.

🖼️ Lectura de imágenes y capturas de pantalla

🧠 Imagínalo así: tú puedes pegar una captura de pantalla de un error en la terminal y Claude Code la analizará visualmente, identificará el problema y sugerirá la solución. Es como tener un par de ojos extra que lee el código en pantalla.

Claude Code es multimodal. Puede leer imágenes de tres formas: pegar desde el portapapeles (Ctrl+V con una captura copiada), hacer referencia a un archivo de imagen en el sistema de archivos (usando @path/to/image.png), o arrastrar y soltar en la terminal (en terminales compatibles). Esto abre un enorme abanico de casos de uso que no existen en los chatbots web tradicionales.

Los casos de uso más comunes son: depuración visual de UI (pega una captura de pantalla del bug, Claude identifica el problema en el CSS/HTML), reproducir un diseño a partir de un mockup (pega la exportación de Figma, pide que lo implemente), y leer diagramas de arquitectura (una foto de una pizarra se convierte en una descripción estructurada). También puedes pasar diagramas UML, gráficos de métricas o capturas de registros con formato.

Ten cuidado con el costo: las imágenes consumen tokens (y muchos). Una captura de pantalla completa puede usar entre 1000 y 2000 tokens. Si el problema se puede describir con texto, prefiere el texto. Reserva las imágenes para cuando la información visual sea realmente necesaria: diseños, colores, posicionamiento, gráficos, capturas de errores.

Ctrl+V (portapapeles)

Toma una captura de pantalla y pégala directamente en la sesión. Es la forma más rápida de resolver bugs visuales.

@archivo.png

Referencia un archivo de imagen en el disco. Ideal para mockups y recursos ya guardados.

Arrastrar y soltar

Arrástralo desde el administrador de archivos hasta la terminal. Funciona en terminales modernos (iTerm2, etc.).

⚠️ Limitaciones de la visión

Claude Code no puede editar imágenes, solo analizarlas. Tampoco lee con precisión texto muy pequeño en screenshots de alta resolución. Para obtener mejores resultados, enfoca el screenshot en el área relevante y usa zoom si es necesario.

En 1 frase: pega capturas de pantalla, indica rutas de imágenes o arrastra archivos y Claude los analiza visualmente.

📤 Salida formateada y pipes de Unix

🧠 Imagínalo así: el modo -p transforma Claude Code en un ciudadano Unix de primera clase. Todo lo que responde va a stdout, listo para canalizar con jq, grep o redirigir a un archivo. Se integra con la filosofía Unix: hace bien una cosa y se conecta con todo.

La integración con el ecosistema Unix es uno de los superpoderes más subestimados de Claude Code. Con claude -p, la salida va directamente a stdout, lo que permite encadenarla con cualquier herramienta Unix. Puedes recibir entrada mediante stdin (entrada por pipe), procesar con Claude y enviar la salida a otra herramienta o archivo. Esto hace que Claude Code sea componible: se convierte en un bloque más de tu cadena de herramientas.

El flag --output-format json hace que Claude devuelva la respuesta en JSON estructurado, lo que es perfecto para el procesamiento automatizado. Combínalo con jq para extraer campos específicos, o con scripts que consumen JSON. Para scripts más complejos, puedes usar --output-format stream-json para recibir tokens en tiempo real mientras el modelo genera.

ejemplos de pipes 
# gerar JSON e processar com jq
claude -p "liste 5 tarefas em JSON" | jq '.[]'

# analisar um arquivo e salvar resultado
claude -p "revise este código" < app.py > review.md

# pipe de entrada: mandar conteúdo para análise
git diff | claude -p "resuma estas mudanças em 3 bullets"

# output em JSON estruturado
claude -p "..." --output-format json

# encadear múltiplas ferramentas
find . -name "*.ts" | head -20 | claude -p "quais desses arquivos são testes?"

🔬 Ejemplo resuelto: revisión automatizada de PR

Un uso real de pipes: automatizar la revisión de código con una sola línea.

git diff main...HEAD | claude -p "Revise este diff. Aponte bugs, melhorias e se segue padroes. Formato: markdown." > review.md

Toma el diff de tu branch contra main, se lo envía a Claude para que lo analice y guarda el resultado en un archivo Markdown. Tarda 10 segundos en ejecutarse y reemplaza 30 minutos de revisión manual en PRs simples.

En 1 frase: claude -p + pipes Unix = IA como herramienta de línea de comandos componible.
