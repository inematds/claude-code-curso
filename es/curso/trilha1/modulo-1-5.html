1

🧠 Cómo funciona la memoria

🧠 Imagínalo así: Claude Code no tiene memoria mágica. Todo lo que «recuerda» vive en la context window de la sesión actual. Es como una mesa de trabajo: lo que está sobre la mesa, lo ve. Lo que se retira, lo olvida.

A memoria de Claude Code es fundamentalmente diferente de la memoria humana. Es efímera por sesión: todo lo que dijiste, todo lo que leyó el agente y todas las respuestas quedan en la ventana de contexto de esa sesión. Cuando termina la sesión, la «memoria» también desaparece.

Lo que persiste entre sesiones es: el CLAUDE.md (leído automáticamente), notas guardadas con /memory, y el propio codebase (que el agente puede volver a leer). Ninguno de estos es memoria del modelo. Son archivos que el modelo vuelve a leer en cada sesión.

En 1 frase: context window = mesa de trabajo temporal; CLAUDE.md y /memory = notas persistentes.

2

💡 El comando /memory

🧠 Imagínalo así: /memory es un atajo para guardar preferencias rápidas sin editar CLAUDE.md. Es como pegar una nota adhesiva en la pantalla de la computadora que permanece entre sesiones.

Dentro de una sesión, escribe /memory abre un editor para guardar notas que Claude Code leerá automáticamente en todas las sesiones futuras de ese proyecto. Internamente, estas notas se almacenan en el CLAUDE.md generado.

Usa /memory para preferencias rápidas: "prefiero respuestas en español", "siempre ejecuta las pruebas antes de hacer commit", "la base de datos de desarrollo está en localhost:5432". Para instrucciones más complejas y estructuradas, edita el CLAUDE.md directamente.

En 1 frase: /memory guarda notas rápidas que persisten entre sesiones sin editar CLAUDE.md manualmente.

3

📐 Ventana de contexto: el recurso escaso

🧠 Imagínalo así: piensa en la context window como la RAM de Claude. Tiene un límite fijo. Cuando la llenas con archivos y conversación, el rendimiento baja. Gestionar el contexto es una habilidad crítica.

La ventana de contexto tiene un límite fijo de aproximadamente 200k tokens. Todo compite por ese espacio: el system prompt (CLAUDE.md), tus mensajes, los archivos que lee el agente, las respuestas generadas y el historial de conversación. A medida que crece la sesión, el espacio disponible disminuye.

En la práctica, una sesión productiva dura entre 30 minutos y 2 horas antes de que el contexto empiece a llenarse. Las sesiones más largas sufren de degradación gradual: el modelo empieza a olvidar detalles del inicio de la conversación, a repetir cosas y a perder el hilo.

⚠️ Señales de contexto lleno

Claude empieza a olvidar instrucciones del principio, repite preguntas que ya respondió, ignora las reglas de CLAUDE.md o simplemente deja de funcionar bien. Cuando lo notes, es hora de compactar el contexto o iniciar una sesión nueva.

En 1 frase: 200k tokens = límite fijo; las sesiones largas se degradan. Gestiona el contexto activamente.

4

🗜️ Compaction — cuándo y cómo

🧠 Imagínalo así: compaction es el «resumen» automático. Cuando el contexto se llena, Claude Code comprime la conversación en un resumen más corto. Libera espacio, pero pierde detalles.

A compaction ocurre de dos formas: automática (cuando el contexto llega a ~95% del límite) o manual (mediante el comando /compact). El proceso resume toda la conversación hasta ese momento en un texto más breve y libera espacio.

La compensación es clara: ganas espacio, pero pierdes matices. Los detalles específicos, las decisiones de código y las explicaciones largas pueden resumirse de forma imprecisa. Por eso es importante hacer checkpoints (hacer commit, guardar notas) antes de que ocurra la compactación.

compactación manual
# compactar manualmente (dentro da sessão)
/compact

# o Claude resume a conversa e libera espaço
# use ANTES de o contexto encher pra ter controle

En 1 frase: /compact resume la conversación para liberar espacio; pierde detalles, así que haz checkpoints antes.

5

🔗 Transferencia de sesión entre conversaciones

🧠 Imagínalo así: cuando una sesión se alarga demasiado, es mejor iniciar una nueva y «pasar el relevo». El arte está en transferir el contexto esencial sin arrastrar basura.

Existen tres estrategias para el handoff entre sesiones: (1) /resume retoma la sesión anterior tal como estaba. (2) Iniciar una sesión nueva con un resumen manual: pídele a Claude «resume lo que hicimos hasta ahora en 10 viñetas» y pega eso en la sesión nueva. (3) Guardar el estado en el CLAUDE.md o en un archivo de notas.

La mejor práctica es combinar: haz commit del código (un checkpoint en git), actualiza CLAUDE.md si algo importante cambió e inicia una sesión nueva. Así, el agente empieza desde cero, pero con todo el contexto necesario en los archivos.

En 1 frase: haz commit del código + actualiza el CLAUDE.md + inicia una sesión nueva = handoff limpio.

6

📍 Estrategias de checkpoint

🧠 Imagínalo así: los checkpoints evitan perder el progreso. El commit de Git es el checkpoint natural. Combínalo con notas en CLAUDE.md y archivos TODO para tareas largas.

O checkpoint lo más natural en el desarrollo es el git commit. Después de cada bloque de trabajo significativo, haz commit. Si el contexto se llena o la sesión se degrada, siempre puedes iniciar una sesión nueva desde el commit más reciente sin perder nada.

Para tareas muy largas (horas de trabajo), agrega checkpoints intermedios: un archivo TODO.md con el estado actual, notas en CLAUDE.md sobre las decisiones tomadas y commits parciales con mensajes descriptivos. Cuando comience la nueva sesión, el agente leerá estos archivos y retomará el trabajo.

estrategia-checkpoint.txt
Tarefa longa? Faça checkpoints:
1. git commit a cada bloco de trabalho
2. Atualize CLAUDE.md se decisões mudaram
3. Use /memory pra notas rápidas
4. Peça ao Claude "resuma o estado atual"
5. Ao iniciar sessão nova, o contexto está nos arquivos

En 1 frase: git commit = punto de control natural; combínalo con CLAUDE.md y TODO.md para tareas largas.
