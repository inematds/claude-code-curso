⚡ Alias de shell para mejorar la productividad

🧠 Imagínalo así: los aliases convierten comandos largos en atajos de 2-3 letras. Cada segundo que ahorras se multiplica por cientos de usos a lo largo de varias semanas.

El primer paso para acelerar tu workflow es crear aliases en tu .bashrc o .zshrc. Claude Code es un comando que vas a escribir decenas de veces al día. Acortarlo claude para cc ya ahorra 4 caracteres por uso.

Además del alias básico, crea aliases para operaciones compuestas que repites con frecuencia: reanudar la última sesión, ejecutar en modo one-shot con un modelo específico o iniciar en una carpeta específica.

aliases recomendados (.bashrc / .zshrc)
# Aliases para Claude Code
alias cc='claude'
alias ccr='claude --resume'
alias ccp='claude -p'
alias cco='claude --model opus'
alias ccs='claude --model sonnet'

# Alias com pipe útil
alias ccgit='git diff | claude -p "resuma estas mudanças"'
alias ccreview='claude -p "revise este arquivo" <'

En 1 frase: aliases como cc, ccr, ccp acortan los comandos y agilizan el día a día.

2

📜 Scripts wrapper personalizados

🧠 Imagínalo así: los scripts wrapper combinan claude -p con otras herramientas en una única operación. Es automatización casera: simple, útil y solo tuya.

Un wrapper es un script de shell que combina Claude Code con otras herramientas. A diferencia de un alias (que es solo un atajo), un wrapper puede tener lógica: verificar condiciones, procesar la salida y guardarla en un archivo.

Ejemplos prácticos: un script que se ejecuta git diff, pásalo a Claude Code para que lo revise y guarda el resultado en un archivo Markdown. O un script que toma un archivo de log, se lo envía a Claude Code para que lo diagnostique y abre el resultado en el editor.

ejemplo: review-pr.sh
#!/bin/bash
# review-pr.sh - Review automatizado de PR
DIFF=$(git diff main...HEAD)
if [ -z "$DIFF" ]; then
  echo "Nenhuma mudança encontrada."
  exit 0
fi
echo "$DIFF" | claude -p "Revise este diff.
Aponte: bugs, melhorias, e se segue os padroes do projeto.
Formato: markdown com seções." > review.md
echo "Review salvo em review.md"

En 1 frase: scripts wrapper = claude -p + lógica de shell para automatizar tareas repetitivas.

3

💻 Integración con VS Code

🧠 Imagínalo así: VS Code es el editor más popular. Usar Claude Code dentro de él (terminal integrado + extensión) crea un workflow en el que nunca necesitas salir del editor.

La forma más sencilla es ejecutar Claude Code en el terminal integrado de VS Code (Ctrl+`). Ves el código arriba y conversas con Claude abajo. Mejor aún: usa dos paneles lado a lado: editor + terminal con Claude Code.

Anthropic también ofrece una extensión oficial de Claude Code para VS Code que se integra más profundamente: el agente aparece como un panel lateral, puede hacer referencia a archivos abiertos y las ediciones aparecen en tiempo real en el editor.

Configuraciones sugeridas de VS Code
{
  "terminal.integrated.defaultProfile.linux": "bash",
  "terminal.integrated.fontSize": 13,
  "editor.formatOnSave": true,
  "workbench.panel.defaultLocation": "right"
}

En 1 frase: el terminal integrado de VS Code + la extensión oficial = Claude Code sin salir del editor.

4

🪟 Multiplexor: tmux/screen + Claude

🧠 Imagínalo así: tmux permite ejecutar Claude Code en sesiones que sobreviven a una desconexión. ¿Cerraste la terminal? Claude sigue ejecutándose. Reconéctate cuando quieras.

O tmux (u screen) es el compañero perfecto de Claude Code para quienes trabajan en servidores remotos o quieren sesiones que no se cierren. Abres un panel con Claude Code y otro con tu editor, y puedes desconectarte y volver a conectarte en cualquier momento.

Una configuración clásica: tmux new-session -s dev, se divide en dos panes (Ctrl+B %), ejecuta claude en uno y edita en el otro. Si necesitas salir, Ctrl+B d se desconecta sin cerrar el proceso. tmux attach -t dev se reconecta.

tmux + Claude Code
# criar sessão
tmux new-session -s claude-dev

# dividir em dois panes
Ctrl+B %     # split vertical
Ctrl+B "     # split horizontal

# rodar claude no pane esquerdo
claude

# desconectar (claude continua rodando)
Ctrl+B d

# reconectar depois
tmux attach -t claude-dev

En 1 frase: tmux crea sesiones persistentes que sobreviven a la desconexión; es ideal para el trabajo remoto.

5

📦 Dotfiles y portabilidad

🧠 Imagínalo así: Los dotfiles versionados en git garantizan que reproduzcas tu configuración en cualquier máquina nueva en minutos. Aliases, configuraciones, CLAUDE.md global: todo versionado.

Crea un repositorio de dotfiles con: .bashrc/.zshrc (aliases), ~/.claude/CLAUDE.md (preferencias globales), ~/.claude/settings.json (configuración global), y un install.sh que crea los symlinks.

Con dotfiles versionados, formatear la máquina o cambiar de computadora deja de ser un trauma. Clona el repo, ejecuta el script de instalación y, en 5 minutos, tu Claude Code estará configurado exactamente como antes.

💡 Estructura sugerida de dotfiles

dotfiles/ → bash/aliases.sh, claude/CLAUDE.md, claude/settings.json, tmux/.tmux.conf, install.sh. install.sh crea enlaces simbólicos de cada archivo a la ubicación correcta en el directorio home.

En 1 frase: dotfiles en git = configuración reproducible en cualquier máquina nueva.

6

🏆 La configuración definitiva para el uso diario

🧠 Imagínalo así: aquí lo juntamos todo: aliases + VS Code + tmux + dotfiles + CLAUDE.md global. El resultado es una configuración que enciendes por la mañana y con la que estás listo para trabajar en 10 segundos.

La configuración completa reúne todas las piezas: aliases en el shell para mayor velocidad, VS Code con terminal integrado para contexto visual, tmux para sesiones persistentes, dotfiles para portabilidad, y CLAUDE.md global para preferencias que se aplican a todos los proyectos.

El ritmo diario ideal: abrir tmux, ejecutar ccr (alias para claude --resume) para retomar donde te quedaste, trabajar durante 1-2 horas, hacer commits de puntos de control y, cuando el contexto se llene, iniciar una sesión nueva. Cada día mejoras la configuración: un alias nuevo por aquí, una regla nueva en CLAUDE.md por allá. En una semana, el workflow ya es visiblemente más rápido que el día 1.
