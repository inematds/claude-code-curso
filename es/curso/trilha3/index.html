🔌 Qué son los servidores MCP

El protocolo MCP explicado desde cero: arquitectura, esquemas y por qué lo cambia todo.

Qué es:

MCP (Model Context Protocol) es el protocolo abierto que conecta LLMs con herramientas externas mediante JSON-RPC.

Por qué aprender:

Es el patrón que Claude Code usa para todas las integraciones externas.

Conceptos clave:

JSON-RPC, transporte stdio/SSE, handshake de capabilities.

Qué es:

Claude Code es el cliente; cada MCP es un servidor que expone tools mediante un schema.

Por qué aprender:

Entender la separación ayuda a depurar y elegir MCPs.

Conceptos clave:

Cliente, servidor, capa de transporte, ciclo de vida.

Qué es:

Cada server declara sus tools con inputSchema de JSON Schema; el client las lista y las invoca.

Por qué aprender:

Es el mecanismo que permite al agente usar herramientas sin código hardcodeado.

Conceptos clave:

tools/list, tools/call, inputSchema, JSON Schema.

Qué es:

MCP transforma al agente de "lector de archivos" en "operador de sistemas".

Por qué aprender:

Sin MCP, el agente solo lee y escribe archivos; con MCP, opera con DBs, APIs y services.

Conceptos clave:

Extensibilidad, composición, estandarización.

Qué es:

Ya existen más de 200 servidores MCP open source que cubren bases de datos, SaaS, DevOps y más.

Por qué aprender:

Saber qué existe evita reinventar la rueda.

Conceptos clave:

Awesome MCP, Smithery, categorías de servers.

Qué es:

MCP es como una API REST, pero optimizada para agentes: schema declarativo, discovery automático.

Por qué aprender:

La analogía facilita entender el modelo mental si ya usaste APIs.

Conceptos clave:

Endpoints REST frente a tools de MCP; OpenAPI frente a inputSchema.

🚀 Tus primeros MCPs

Manos a la obra: configurar Filesystem, Git y SQLite en Claude Code.

Qué es:

El archivo .claude/settings.json donde declaras cada servidor MCP.

Por qué aprender:

Sin esto, ningún MCP funciona; es el primer paso práctico.

Conceptos clave:

mcpServers, command, args, env.

Qué es:

Server que expone operaciones del filesystem como tools MCP.

Por qué aprender:

Es el MCP más básico e ilustra perfectamente el patrón.

Conceptos clave:

read_file, write_file, list_directory, sandboxing.

Qué es:

Server MCP para operaciones Git: status, diff, commit, branch.

Por qué aprender:

Permite que el agente versione código sin que tengas que intervenir manualmente.

Conceptos clave:

git_status, git_commit, git_diff, permisos.

Qué es:

Server que da al agente acceso SQL a bases de datos SQLite.

Por qué aprender:

Muestra cómo los MCP pueden dar acceso a datos estructurados.

Conceptos clave:

query, execute, schema inspection, read-only mode.

Qué es:

Cómo verificar si el MCP está conectado y las tools aparecen en el agente.

Por qué aprender:

Sin pruebas, no sabes si la configuración está bien.

Conceptos clave:

/mcp, listado de herramientas, invocación manual, logs.

Qué es:

Diagnosticar errores comunes: el server no inicia, timeout, permission denied.

Por qué aprender:

El 90% de los problemas con MCP son de configuración; saber depurar ahorra horas.

Conceptos clave:

stderr logs, npx vs global install, PATH, env vars.

🛠️ Crea tu propio servidor MCP

Desde cero hasta el deploy: anatomía, SDK TypeScript, tools, handlers y distribución.

Qué es:

Un servidor MCP es un proceso que se comunica mediante JSON-RPC por stdio y expone tools.

Por qué aprender:

Entender la anatomía es un requisito previo para crear el tuyo.

Conceptos clave:

Proceso, stdin/stdout, initialize, handler de tools/list.

Qué es:

El paquete @modelcontextprotocol/sdk que abstrae el protocolo por ti.

Por qué aprender:

Con el SDK, creas un server funcional en 30 líneas.

Conceptos clave:

Clase McpServer, StdioServerTransport, tool(), resource().

Qué es:

Cada tool tiene nombre, descripción y un inputSchema (JSON Schema) que el agente usa.

Por qué aprender:

Un schema bien diseñado = el agente acierta los parámetros a la primera.

Conceptos clave:

name, description, inputSchema, required fields, types.

Qué es:

La función que recibe los argumentos del agente, ejecuta la acción y devuelve el resultado.

Por qué aprender:

Es donde vive la lógica real; el handler es el "cuerpo" de la tool.

Conceptos clave:

CallToolResult, matriz content, respuestas text/image, manejo de errores.

Qué es:

Probar el servidor MCP localmente con MCP Inspector y Claude Code.

Por qué aprender:

Un servidor sin pruebas falla en silencio; el inspector facilita mucho las cosas.

Conceptos clave:

MCP Inspector, JSON-RPC manual, pruebas de integración.

Qué es:

Cómo empaquetar y publicar tu servidor MCP (npm, Docker, Smithery).

Por qué aprender:

Compartirlo con el equipo o la comunidad multiplica el impacto.

Conceptos clave:

npm publish, npx entry point, Docker image, publicación en Smithery.

🌐 Ecosistema y Marketplace

Dónde encontrar, evaluar y combinar servidores MCP de calidad.

Qué es:

El repositorio awesome-mcp-servers en GitHub: la lista curada por la comunidad.

Por qué aprender:

Punto de partida para descubrir MCP de alta calidad ya disponibles.

Conceptos clave:

Categorías, estrellas, mantenimiento activo, oficiales vs. comunitarios.

Qué es:

Smithery.ai: el npm/marketplace para MCP servers con instalación con un clic.

Por qué aprender:

Instalar MCP mediante Smithery es más rápido que configurarlos manualmente.

Conceptos clave:

smithery install, verified servers, usage stats.

Qué es:

Criterios para evaluar si un MCP server es confiable antes de usarlo.

Por qué aprender:

Un MCP deficiente puede bloquearse, filtrar datos o dar respuestas incorrectas.

Conceptos clave:

Commits recientes, issues abiertas, documentación, pruebas, licencia.

Qué es:

Patrones para combinar de 3 a 8 MCPs en una configuración coherente y productiva.

Por qué aprender:

El poder de MCP se manifiesta en la composición, no en servers aislados.

Conceptos clave:

Presupuesto de tools, conflictos de nombres, enrutamiento prioritario.

Qué es:

Riesgos de MCP maliciosos y cómo protegerte (sandbox, auditoría, privilegio mínimo).

Por qué aprender:

Un MCP ejecuta código en tu máquina; confiar ciegamente es peligroso.

Conceptos clave:

Revisión de código, versiones fijadas, sandboxing, ámbitos de permisos.

Qué es:

Tendencias: servidores remotos, autenticación federada, streaming, herramientas multimodales.

Por qué aprender:

Saber la dirección ayuda a invertir en lo que perdurará.

Conceptos clave:

Remote MCP, OAuth2, Streamable HTTP, composición de herramientas.
