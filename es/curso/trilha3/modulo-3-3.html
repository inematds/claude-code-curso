💬 Slack MCP

El Slack MCP conecta al agente con los canales y mensajes directos de tu workspace. Tools típicas: read_channel (leer mensajes recientes), send_message (enviar mensaje), search_messages (buscar en el historial). Necesitas un OAuth Bot Token configurado como variable de entorno.

Caso de uso real: pides "resume los últimos 50 mensajes del canal #engineering" y el agente los lee, procesa y te da un resumen. O "publica en #standup: implementación del módulo X completada" y lo publica por ti.

settings.json (slack)
"slack": {
  "command": "npx",
  "args": ["-y", "@anthropic/mcp-server-slack"],
  "env": {
    "SLACK_BOT_TOKEN": "xoxb-seu-token-aqui"
  }
}

En 1 frase: Slack MCP = leer, enviar y buscar mensajes de Slack mediante el agente.

2

📆 Google Calendar MCP

Con Calendar MCP, el agente puede listar eventos (list_events), crear reuniones (create_event), comprobar disponibilidad (check_availability). Necesitas una Service Account o configurar OAuth2 de Google.

Ejemplo práctico: "¿cuál es mi agenda de mañana?" y el agente consulta los eventos, los resume y destaca los conflictos. O "agenda una llamada con Joao mañana a las 14h" y crea el evento directamente.

En 1 frase: Calendar MCP = ver, crear y gestionar eventos de Google Calendar mediante un agente.

3

📧 MCP de Gmail

El Gmail MCP expone tools para search_emails, read_email, send_email, create_draft. El agente puede hacer una clasificación inicial de la bandeja de entrada: leer correos no leídos, resumirlos e incluso redactar respuestas para que las revises.

Ten cuidado con los permisos: send_email envía de verdad. Si solo quieres hacer una clasificación inicial, usa create_draft en lugar de send, y revísalo antes de enviarlo.

Ten cuidado con send_email

El agente puede enviar correos electrónicos de verdad. Si no quieres eso, configura el MCP en modo read-only o elimina la herramienta send_email de los permisos en settings.json.

En 1 frase: Gmail MCP = clasificación, búsqueda y borradores de correos directamente en el agente.

4

📝 MCP de Notion/Linear

MCP para la gestión de proyectos: el Notion MCP permite crear pages, buscar docs, actualizar databases. El Linear MCP permite crear issues, listar sprints, actualizar estados. Ambos necesitan API keys en el env.

Escenario: el agente termina una tarea de código, crea automáticamente una issue de revisión en Linear y documenta el cambio en Notion. Cero trabajo manual de gestión.

En 1 frase: Notion/Linear MCPs = documentación e issues automáticas, sin salir del agente.

5

🔗 Combinación de varios MCP

El verdadero poder de MCP se manifiesta cuando ejecutas 3-5 servers al mismo tiempo. El agente ve todas las herramientas de todos los servidores y puede orquestar entre ellos. Ejemplo: "lee el correo del cliente, crea una issue en Linear y avisa en Slack" = tres MCP en una sola instrucción.

Ten cuidado con el presupuesto de herramientas: cada tool que el agente ve consume tokens de contexto (el schema queda en el system prompt). Con 50+ tools, el costo de contexto aumenta. Conserva solo los MCP que realmente usas en el día a día.

En 1 frase: varios MCP simultáneos = el agente orquesta operaciones entre herramientas sin código.

6

⚡ Automatizaciones del día a día

Recetas listas para copiar y adaptar:

Morning briefing

"Lee mis correos no leídos, muéstrame mi agenda de hoy y resume los últimos mensajes de #general en Slack."

Notificación después del deploy

"Envía en Slack #deploys: 'Deploy v2.3 completado' y crea una page en Notion con el changelog."

Email triage

"Lee los 20 correos más recientes, clasifícalos por urgencia y redacta respuestas para los urgentes."

Sprint review

"Enumera las issues completadas en Linear esta semana y genera un resumen para el standup."

En 1 frase: combina MCP de productividad en workflows que se ejecutan con una sola instrucción.
