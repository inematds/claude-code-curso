1

⭐ Awesome MCP — los mejores

El repositorio awesome-mcp-servers en GitHub y es la lista seleccionada por la comunidad con los mejores MCP servers. Está organizada por categoría (DevOps, Database, SaaS, Cloud, etc.), con enlaces directos y descripciones. Es el punto de partida para descubrir qué existe antes de crear el tuyo.

Consejo: ordena por estrellas y fecha del último commit. Un MCP con muchas estrellas pero sin commits desde hace 6 meses puede estar abandonado.

En 1 frase: awesome-mcp-servers = lista curada en GitHub, punto de partida para descubrir.

2

🏪 Smithery y registros

Smithery.ai es el marketplace emergente de servidores MCP. Funciona como un npm para MCP: buscas, instalas con un comando y ya queda configurado. Los servidores verificados tienen un sello de calidad.

La ventaja de Smithery sobre awesome-mcp es la instalación simplificada y las métricas de uso. La desventaja es que es más nuevo y todavía no tiene todo.

En 1 frase: Smithery.ai = marketplace con instalación simplificada y servers verificados.

3

🔍 Evaluación de calidad

No todos los servidores MCP sirven. Antes de usar uno, comprueba: (1) ¿Tiene commits recientes? (2) ¿Cuántos issues están abiertos frente a los resueltos? (3) ¿Tiene documentación? (4) ¿Tiene pruebas? (5) ¿La licencia es compatible? Un servidor sin commits desde hace meses y sin pruebas es un riesgo.

Lista rápida: último commit < 3 meses, más de 10 estrellas, README con ejemplos, pruebas en CI, licencia MIT/Apache. Si cumple 4 de 5, es seguro usarlo.

En 1 frase: evaluar = commits recientes + issues + docs + pruebas + licencia.

4

🧩 Composición de servidores

El verdadero poder de MCP está en la composición: ejecutar 3-8 servers simultáneamente que se complementen. Patrones: stack de desarrollo (Git + Filesystem + SQLite), stack de operaciones (Postgres + Redis + monitoring), stack de productividad (Slack + Calendar + Gmail).

Ten cuidado con los conflictos de nombres: si dos servers tienen una tool con el mismo nombre, el comportamiento es indefinido. Prefiere servers que usen prefijos únicos en los nombres de las tools.

Stacks recomendados

Dev Stack

Git + Sistema de archivos + SQLite + Browser

Ops Stack

Postgres + Redis + Docker + AWS

Productividad

Slack + Calendar + Gmail + Linear

En 1 frase: composición = combinar 3-8 MCP en stacks temáticos; evitar conflictos de nombres.

5

🛡️ Seguridad y confianza

Un servidor MCP ejecuta código en tu máquina. Si es malicioso, puede leer tus archivos, robar tokens o destruir datos. Antes de instalarlo: (1) lee el código fuente, (2) prefiere servidores oficiales o con muchas stars, (3) usa versiones fijadas (no latest), (4) ejecútalo en un sandbox cuando sea posible.

Principio del menor privilegio: dale al MCP solo el acceso que necesita. Si solo necesita leer, no le des permisos de escritura. Si solo necesita un directorio, no le des acceso a todo el sistema de archivos.

En 1 frase: MCP = código en tu máquina; confía con cuidado, usa least-privilege.

6

🔮 El futuro de MCP

El protocolo MCP está evolucionando rápidamente. Tendencias: Remote MCP (servidores que se ejecutan en la nube, no localmente), OAuth2 nativo (autenticación estandarizada sin tokens manuales), Streamable HTTP (reemplaza SSE con mejor rendimiento), y multi-modal tools (devolver imágenes, audio, video).

Invertir en MCP ahora es como haber invertido en REST en 2010: el estándar todavía va a cambiar, pero la dirección está clara. Quien aprende los fundamentos hoy queda bien posicionado para lo que venga.

En 1 frase: MCP evoluciona rápido: remote servers, OAuth2, streaming; aprender ahora te prepara para el futuro.
