⚡ Atalhos de teclado essenciais

🧠 Imagine assim: atalhos de teclado no Claude Code sao como os atalhos no Vim. No começo voce ignora, depois de aprender nao vive sem. A diferença e que aqui sao apenas 5-6 teclas que cobrem tudo.

Dentro da sessão interativa do Claude Code, algumas teclas tem comportamento especial que acelera drasticamente seu workflow. O segredo e que sao poucas: cinco atalhos cobrem 95% da interação. Saber essas cinco teclas transforma a experiencia de "digitar e esperar" para "controlar o fluxo com precisão". E a diferença entre dirigir automatico e manual: no automatico voce fica a merce da IA, no manual voce decide quando frear, quando acelerar, quando voltar atras.

O mais importante de todos e o Escape: ele cancela a operação corrente e te devolve ao prompt limpo. Quando o Claude esta editando um arquivo e voce percebe que ele esta indo pro caminho errado, Escape para tudo. Em seguida vem o Tab para aceitar sugestões do autocomplete, Ctrl+C para interromper uma geração longa que ja deu o que tinha que dar, Shift+Tab para rejeitar uma sugestão, e Enter duplo para enviar mensagens multi-linha. Com essas cinco, voce navega qualquer sessão.

✓ Atalhos essenciais

  • • Escape — cancela a ação corrente / volta ao prompt
  • • Tab — aceita sugestão / autocomplete
  • • Ctrl+C — interrompe a geração em andamento
  • • Shift+Tab — rejeita sugestão
  • • Enter duplo — envia mensagem multi-linha

→ Dicas de navegação

  • • Seta para cima — editar ultima mensagem
  • • Ctrl+L — limpar tela (sem perder contexto)
  • • / no inicio — abre slash commands
  • • @ — referenciar arquivo por nome
  • • Colar imagem — analise visual automatica

💡 Dica: pratique os atalhos

Na proxima sessão com o Claude Code, force-se a usar apenas atalhos por 10 minutos. Peça algo, cancele com Escape, peça de novo, aceite com Tab, interrompa com Ctrl+C. Em menos de uma hora voce ja esta no piloto automatico e nunca mais volta ao modo lento.

Em 1 frase: Escape, Tab, Ctrl+C, Shift+Tab e Enter duplo cobrem 95% da interação.

🔧 Slash commands — o painel de controle

🧠 Imagine assim: slash commands sao o painel de controle escondido do Claude Code. Digitou /, apareceu um menu. E como o command palette do VS Code, mas dentro da conversa com a IA.

Dentro de uma sessão interativa, digitar / no inicio da mensagem ativa os slash commands. Eles controlam a sessão sem gastar tokens de conversa. Enquanto uma mensagem normal vai pro modelo (e consome contexto), um slash command e executado localmente: nao gasta nada, age na hora.

Os mais usados formam um kit basico que todo usuario deveria memorizar. /help lista tudo que esta disponivel. /clear zera o contexto da conversa (util quando o contexto ficou poluido). /compact comprime a conversa num resumo menor para liberar espaço. /model mostra ou troca o modelo. /memory salva preferências que persistem entre sessões. /cost mostra quanto voce gastou na sessão. E /resume retoma uma sessão anterior.

slash commands essenciais 
/help       — lista todos os comandos disponíveis
/clear      — limpa o contexto da conversa atual
/compact    — comprime o contexto para liberar espaço
/model      — ver ou trocar o modelo em uso
/memory     — salvar uma nota persistente
/resume     — retomar sessão anterior
/cost       — ver quanto gastou na sessão atual
/config     — abrir configurações

/help

O ponto de partida. Mostra tudo que esta disponivel. Rode quando estiver perdido.

/clear

Apaga todo o contexto. Util quando voce quer recomeçar sem fechar o terminal.

/compact

Comprime a conversa num resumo para liberar contexto. Use antes de o contexto encher.

/model

Mostra qual modelo esta ativo. Pode trocar entre Opus e Sonnet sem sair da sessão.

/memory

Salva uma preferência que persiste entre sessões. Exemplo: "sempre use TypeScript".

Em 1 frase: digite / para acessar o painel de controle do Claude Code dentro da sessão.

3

🧠 Modelo e janela de contexto

🧠 Imagine assim: o modelo e o cerebro; a janela de contexto e a memória de trabalho. Imagine que o Claude tem uma mesa de trabalho com espaço limitado. Tudo que voce diz e tudo que ele le vai pra mesa. Quando enche, algo cai.

O Claude Code usa modelos da familia Claude da Anthropic. O padrao costuma ser o Claude Sonnet (rapido e capaz para a maioria das tarefas), mas voce pode mudar para Claude Opus (mais profundo, melhor em raciocinio complexo e codebases grandes) a qualquer momento com /model ou --model. Entender a diferença entre eles e saber quando trocar e uma habilidade que separa usuarios eficientes de usuarios que desperdiçam dinheiro ou tempo.

A janela de contexto e o limite do que o modelo ve ao mesmo tempo: tudo que voce disse, tudo que ele leu, todos os arquivos inspecionados, todas as respostas geradas. O context window do Claude e de aproximadamente 200k tokens (cerca de 150k palavras). Parece muito, mas um codebase medio consome isso rapido. Cada arquivo lido, cada resposta gerada, cada CLAUDE.md carregado come tokens dessa janela. Quando o espaço acaba, o Claude começa a esquecer o inicio da conversa.

✓ Claude Sonnet

  • • Rapido e responsivo
  • • Bom para tarefas comuns
  • • Mais barato por token
  • • Ideal para edições rapidas e perguntas

→ Claude Opus

  • • Mais profundo e preciso
  • • Melhor em raciocinio complexo
  • • Mais caro por token
  • • Ideal para refatoração e arquitetura

⚠️ Sinais de contexto cheio

O Claude começa a esquecer instruções do inicio, repete perguntas ja respondidas, ignora regras do CLAUDE.md, ou simplesmente para de funcionar bem. Quando perceber isso, use /compact ou inicie sessão nova.

Em 1 frase: Sonnet = rapido, Opus = profundo; 200k tokens e a mesa de trabalho e tudo compete por espaço.

4

💾 Sessões e /resume

🧠 Imagine assim: fechar o terminal nao apaga a conversa. E como fechar um livro com marcador. Quando voce volta, o /resume abre na pagina certa.

O Claude Code persiste sessões automaticamente no disco local. Cada conversa tem um session ID e fica salva em ~/.claude/. Isso significa que fechar o terminal, desligar o computador, ou ate trocar de aba nao perde nada. A sessão continua la, esperando voce voltar.

Para retomar, voce tem duas opções: claude --resume na linha de comando (antes de abrir uma sessão nova) ou /resume de dentro de uma sessão ja aberta. Ambos mostram um picker com as sessões recentes para voce escolher. Tambem e possivel retomar uma sessão especifica pelo ID: claude --resume SESSION_ID.

Na pratica, o ritmo ideal e: trabalhar numa sessão por 1-2 horas, commitar checkpoints no git, e quando o contexto encher, iniciar sessão nova. Se precisar retomar algo do dia anterior, --resume recupera. Mas lembre: sessões muito longas degradam a qualidade das respostas porque o contexto fica lotado. As vezes e melhor começar fresco e deixar o CLAUDE.md carregar o contexto essencial.

retomando sessões 
# retomar a última sessão
claude --resume

# dentro de uma sessão, retomar outra
/resume

# continuar conversa específica por ID
claude --resume SESSION_ID

# listar sessões recentes
claude --resume  (mostra picker interativo)

💡 Sessão nova vs resume

Se voce esta retomando o mesmo trabalho de ontem, use --resume. Se voce esta começando uma tarefa diferente (mesmo no mesmo projeto), inicie sessão nova. Misturar contextos de tarefas diferentes polui a janela e degrada a qualidade.

Em 1 frase: sessões persistem no disco; --resume ou /resume retoma de onde voce parou.

🖼️ Leitura de imagens e screenshots

🧠 Imagine assim: voce pode colar um screenshot de um bug no terminal e o Claude Code vai analisar visualmente, identificar o problema e sugerir o fix. E como ter um par de olhos extra que lê codigo na tela.

O Claude Code e multimodal. Ele pode ler imagens de tres formas: colar do clipboard (Ctrl+V com um screenshot copiado), referenciar um arquivo de imagem no filesystem (usando @path/to/image.png), ou arrastar e soltar no terminal (em terminais que suportam). Isso abre um leque enorme de casos de uso que nao existem em chatbots web tradicionais.

Os casos de uso mais comuns sao: debug visual de UI (cole um screenshot do bug, o Claude identifica o problema no CSS/HTML), reproduzir um design a partir de um mockup (cole o Figma export, peça para implementar), e ler diagramas de arquitetura (foto de um quadro branco vira descrição estruturada). Voce tambem pode passar diagramas UML, graficos de metricas, ou prints de logs formatados.

Cuidado com o custo: imagens consomem tokens (e bastante). Um screenshot de tela cheia pode usar 1000-2000 tokens. Se o problema pode ser descrito em texto, prefira texto. Reserve imagens para quando a informação visual e genuinamente necessaria: layouts, cores, posicionamento, graficos, screenshots de erro.

Ctrl+V (clipboard)

Tire um screenshot, cole diretamente na sessão. O jeito mais rapido para bugs visuais.

@arquivo.png

Referencia um arquivo de imagem no disco. Ideal para mockups e assets ja salvos.

Drag & Drop

Arraste do file manager pro terminal. Funciona em terminais modernos (iTerm2, etc).

⚠️ Limitações da visao

O Claude Code nao consegue editar imagens, apenas analisa-las. Ele tambem nao le texto muito pequeno em screenshots de alta resolução com precisao. Para melhor resultado, foque o screenshot na area relevante e use zoom se necessario.

Em 1 frase: cole screenshots, passe paths de imagem ou arraste arquivos e o Claude analisa visualmente.

📤 Output formatado e pipes Unix

🧠 Imagine assim: o modo -p transforma o Claude Code em um cidadão Unix de primeira classe. Tudo o que ele responde vai pro stdout, pronto para pipar com jq, grep, ou redirecionar para um arquivo. Ele se encaixa na filosofia Unix: faz uma coisa bem e se conecta com tudo.

A integracao com o ecossistema Unix e um dos superpoderes mais subestimados do Claude Code. Com claude -p, a saida vai diretamente pro stdout, permitindo encadear com qualquer ferramenta Unix. Voce pode receber entrada via stdin (pipe de entrada), processar com o Claude, e mandar a saida para outra ferramenta ou arquivo. Isso torna o Claude Code composivel: ele vira mais um bloco na sua cadeia de ferramentas.

A flag --output-format json faz o Claude devolver a resposta em JSON estruturado, o que e perfeito para processamento automatizado. Combine com jq para extrair campos especificos, ou com scripts que consomem JSON. Para scripts mais complexos, voce pode usar --output-format stream-json para receber tokens em tempo real conforme o modelo gera.

exemplos de pipes 
# gerar JSON e processar com jq
claude -p "liste 5 tarefas em JSON" | jq '.[]'

# analisar um arquivo e salvar resultado
claude -p "revise este código" < app.py > review.md

# pipe de entrada: mandar conteúdo para análise
git diff | claude -p "resuma estas mudanças em 3 bullets"

# output em JSON estruturado
claude -p "..." --output-format json

# encadear múltiplas ferramentas
find . -name "*.ts" | head -20 | claude -p "quais desses arquivos são testes?"

🔬 Exemplo resolvido: review automatizado de PR

Um uso real de pipes: automatizar code review com uma unica linha.

git diff main...HEAD | claude -p "Revise este diff. Aponte bugs, melhorias e se segue padroes. Formato: markdown." > review.md

Isso pega o diff da sua branch contra main, manda pro Claude analisar, e salva o resultado num arquivo Markdown. Leva 10 segundos para rodar e substitui 30 minutos de review manual em PRs simples.

Em 1 frase: claude -p + pipes Unix = IA como ferramenta de linha de comando composivel.
