📦 Installation and First Command

From npm install to your first working prompt. Everything you need to start using Claude Code today.

What is:

The three ways to install Claude Code: npm, Homebrew, and winget.

Why learn:

Without the right installation, nothing else works.

Key concepts:

Node.js 18+; global npm install; API key authentication.

What is:

Run the claude command for the first time and understand what appears.

Why learn:

The first real step. Without it, the rest is theory.

Key concepts:

Interactive interface; Claude prompt; inline response.

What is:

claude (interactive) vs. claude -p "question" (one-shot, no session).

Why learn:

Knowing when to use each mode saves time and context.

Key concepts:

Interactive mode = conversation; -p flag = one-shot; pipes with -p.

What is:

The flags you'll use every day: --help, --version, -p, --model, --verbose.

Why learn:

Knowing the flags keeps you from getting lost on Google.

Key concepts:

--help as a quick reference; most-used flags.

What is:

How to update Claude Code and check the installed version.

Why learn:

New versions bring important features and fixes.

Key concepts:

npm update -g; changelog; breaking changes.

What is:

The most common installation errors and how to fix each one.

Why learn:

Knowing how to fix errors keeps you from getting stuck right at the start.

Key concepts:

EACCES permission; Node version mismatch; auth errors.

Keyboard shortcuts, slash commands, sessions, and pipes that multiply your speed.

What is:

Claude Code keyboard shortcuts: Escape, Tab, Ctrl+C, and more.

Why learn:

Shortcuts save clicks and keep you focused on the terminal.

Key concepts:

Escape to cancel; Tab to accept; Ctrl+C to interrupt.

What is:

Slash commands inside the Claude Code interactive session.

Why learn:

They are the control panel within the conversation.

Key concepts:

/help; /clear; /model; /memory; /resume; /compact.

What is:

Which model runs behind Claude Code, and how does context work?

Why learn:

Understanding the model helps you calibrate expectations and costs.

Key concepts:

Opus/Sonnet; context window; token budget.

What is:

Sessions persist between runs. /resume picks up the previous conversation.

Why learn:

Don't lose your work context when you close the terminal.

Key concepts:

Session ID; /resume; --resume flag; session picker.

What is:

Claude Code reads images from the filesystem and analyzes screenshots.

Why learn:

Visual debugging, reproducing designs, reading diagrams.

Key concepts:

Drag-and-drop; paste a screenshot; reference by path.

What is:

Use claude -p with Unix pipes: | jq, | grep, > file.

Why learn:

Native integration with the Unix ecosystem multiplies its power.

Key concepts:

Stdout; --output-format json; piping with jq; wrapper scripts.

🧠 CLAUDE.md — The Project's Brain

The file that turns Claude Code from a general-purpose tool into a specialist in your project.

What is:

A Markdown file that Claude Code reads automatically in every session.

Why learn:

It’s the only way to give the agent persistent context about your project.

Key concepts:

System prompt; persistent instructions; project context.

What is:

~/.claude/CLAUDE.md (global) > ./CLAUDE.md (project) > subdir/CLAUDE.md (folder).

Why learn:

Each level solves a different scope problem.

Key concepts:

Instruction cascade; inheritance; override by level.

What is:

How to write a CLAUDE.md that the model actually follows.

Why learn:

A poorly written CLAUDE.md gets ignored; a good one changes everything.

Key concepts:

Clear headings; lists; examples; imperative tone.

What is:

Which types of instructions actually change the agent’s behavior.

Why learn:

Fewer, right instructions > many vague instructions.

Key concepts:

Stack; conventions; prohibitions; project standards.

What is:

Annotated examples of CLAUDE.md files from real projects.

Why learn:

Seeing real examples shortens the learning curve.

Key concepts:

Common patterns; anti-patterns; ideal size.

What is:

CLAUDE.md should evolve along with the project and be committed to git.

Why learn:

An outdated CLAUDE.md is worse than none at all.

Key concepts:

Commit to the repo; review monthly; /memory as a supplement.

💾 Memory and Persistent Context

How memory works, what a context window is, compaction, and strategies to avoid losing context.

What is:

Claude Code doesn't have magical memory. Everything lives in the session's context window.

Why learn:

Understanding the mental model prevents frustration with “it forgot.”

Key concepts:

Context window = working memory; CLAUDE.md = persistent memory.

What is:

/memory saves persistent notes that Claude Code reads in every future session.

Why learn:

It’s the quick way to teach preferences without editing CLAUDE.md.

Key concepts:

/memory; generated CLAUDE.md; ~/.claude/CLAUDE.md.

What is:

The context window has a fixed limit (200k tokens). Everything competes for space.

Why learn:

When the context fills up, the quality of the responses drops.

Key concepts:

Tokens; context limit; gradual degradation.

What is:

Claude Code automatically summarizes the conversation when the context fills up.

Why learn:

Compaction loses details. Knowing when it will happen helps you prepare.

Key concepts:

/compact manual; auto-compaction; what gets lost.

What is:

Strategies for transferring context from one session to another.

Why learn:

Long sessions degrade. Knowing when to split them keeps quality high.

Key concepts:

/resume; manual summary; CLAUDE.md as handoff.

What is:

Techniques for saving the state of your work before the context fills up.

Why learn:

Checkpoints prevent progress loss on long tasks.

Key concepts:

Git commits as checkpoints; notes in CLAUDE.md; TODO files.
