🔌 What MCP Servers Are

The MCP protocol explained from scratch: architecture, schemas, and why it changes everything.

What is:

MCP (Model Context Protocol) is the open protocol that connects LLMs to external tools via JSON-RPC.

Why learn:

It's the standard Claude Code uses for all external integrations.

Key concepts:

JSON-RPC, stdio/SSE transport, capabilities handshake.

What is:

Claude Code is the client; each MCP is a server that exposes tools via a schema.

Why learn:

Understanding the separation helps you debug and choose MCPs.

Key concepts:

Client, server, transport layer, lifecycle.

What is:

Each server declares its tools with an inputSchema in JSON Schema; the client lists and invokes them.

Why learn:

It's the mechanism that lets the agent use tools without hardcoding them.

Key concepts:

tools/list, tools/call, inputSchema, JSON Schema.

What is:

MCP turns the agent from a "file reader" into a "systems operator."

Why learn:

Without MCP, the agent only reads/writes files; with MCP, it operates DBs, APIs, services.

Key concepts:

Extensibility, composition, standardization.

What is:

There are already 200+ open-source MCP servers covering databases, SaaS, DevOps, and more.

Why learn:

Knowing what exists keeps you from reinventing the wheel.

Key concepts:

Awesome MCP, Smithery, server categories.

What is:

MCP is like a REST API, but optimized for agents: declarative schema, automatic discovery.

Why learn:

The analogy makes it easier to understand the mental model if you've used APIs before.

Key concepts:

REST endpoints vs. MCP tools; OpenAPI vs. inputSchema.

🛠️ Creating Your Own MCP Server

From zero to deploy: anatomy, TypeScript SDK, tools, handlers, and distribution.

What is:

An MCP server is a process that speaks JSON-RPC over stdio and exposes tools.

Why learn:

Understanding the anatomy is a prerequisite to creating your own.

Key concepts:

Process, stdin/stdout, initialize, tools/list handler.

What is:

The @modelcontextprotocol/sdk package that abstracts the protocol for you.

Why learn:

With the SDK, you can create a working server in 30 lines.

Key concepts:

McpServer class, StdioServerTransport, tool(), resource().

What is:

Each tool has a name, description, and an inputSchema (JSON Schema) that the agent uses.

Why learn:

A well-designed schema = the agent gets the parameters right the first time.

Key concepts:

name, description, inputSchema, required fields, types.

What is:

The function that receives the agent's args, performs the action, and returns the result.

Why learn:

It's where the actual logic lives; the handler is the tool's "body."

Key concepts:

CallToolResult, content array, text/image responses, error handling.

What is:

Test the MCP server locally with MCP Inspector and Claude Code.

Why learn:

A server without tests breaks silently; the inspector makes things much easier.

Key concepts:

MCP Inspector, manual JSON-RPC, integration tests.

What is:

How to package and publish your MCP server (npm, Docker, Smithery).

Why learn:

Sharing with your team or community multiplies the impact.

Key concepts:

npm publish, npx entry point, Docker image, Smithery listing.
